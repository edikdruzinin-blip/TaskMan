# TaskMan: диспетчер задач для Android в стиле Windows

Kotlin + Jetpack Compose. Работает с любым `su`: **KernelSU, Magisk, APatch**. Без root запускается, но видит только себя (так устроен Android).

## Что внутри

| Вкладка | Что показывает и что можно сделать |
|---|---|
| **Процессы** | Группы «Приложения / Фоновые / Системные», как в Windows. На телефоне строка — карточка: имя и пакет, под ними Диск/Сеть, справа ЦП и Память; на широком экране — таблица с четырьмя столбцами и тепловой подсветкой. Нажатие открывает действия: завершить задачу (`am force-stop`), завершить процесс (SIGKILL / SIGTERM), приостановить / продолжить (SIGSTOP / SIGCONT), приоритет (nice), свойства (exe, SELinux-контекст, PSS, swap, cgroup), **поиск в Интернете**, «О приложении», **открыть расположение файла** (папка APK или исполняемого файла) и папку данных приложения. |
| **Производительность** | ЦП (общий график и по ядрам, частоты), **оперативная память** (состав, swap, **ZRAM со степенью сжатия**), **память** (как «Диск» в Windows: время активности, скорость чтения и записи, время отклика, заполнение раздела данных, сколько прочитано и записано с загрузки), мобильный интернет, Wi-Fi (скорость, SSID, сигнал, диапазон, IP), графический процессор (нагрузка, частота, **ядра и потоки**, если их отдаёт драйвер). На телефоне плитки идут сеткой 2×3, а не горизонтальной лентой. |
| **Автозагрузка** | Приложения с приёмниками `BOOT_COMPLETED` / `LOCKED_BOOT_COMPLETED` / `QUICKBOOT_POWERON` (пользовательские и системные, с фильтрами), переключатель включает или отключает приёмники через `pm`. Плюс **модули Magisk / KernelSU / APatch** и скрипты `service.d` / `post-fs-data.d`. |
| **Сведения** | Все процессы: PID, состояние, пользователь, ЦП, память, потоки, nice, OOM adj. На телефоне — компактный список в две-три строки, на широком экране — таблица. Сортировка по любому полю, те же действия по нажатию. |
| **Службы** | Запущенные службы Android (`dumpsys activity services`) и нативные службы init (`init.svc.*`) с запуском, остановкой, перезапуском. |

Сверху: поиск по имени, пакету или PID, меню с **темой**, скоростью обновления (1 с / 2 с / 5 с / пауза) и показом потоков ядра. На телефоне вкладки перенесены вниз, в зону большого пальца; на широком экране остаются сверху. Тема и скорость запоминаются.

**Списки процессов** («Процессы» и «Сведения») обновляются не чаще раза в 3 секунды (при низкой скорости обновления — реже) и стоят на месте, пока вы их прокручиваете, чтобы строка не уехала из-под пальца. Нагрузка ЦП в них усредняется за это окно. Графики во вкладке «Производительность» идут со скоростью обновления из меню.

На телефоне списки процессов — карточки в две-три строки: имя и пакет, под ними Диск/Сеть, справа ЦП и Память; сортировка вынесена в меню «Сортировка». В «Сведениях» на телефоне компактный список, а не широкая таблица. На широком экране (планшет или крупный телефон в альбомной ориентации) возвращается таблица со всеми столбцами.

### Открыть расположение файла

Пункт есть у приложений, процессов, автозагрузки и служб. Открывается встроенный обозреватель папок: он читает каталоги через root-оболочку, поэтому заходит в `/data/app`, `/data/data`, `/system` и другие места, недоступные обычным файловым менеджерам. Нужный файл подсвечен (для приложения это `base.apk`, для демона его исполняемый файл).

- нажатие на папку заходит в неё, на файл копирует его путь;
- кнопка «Назад» поднимается на уровень вверх, крестик закрывает обозреватель;
- «Копировать путь» берёт путь подсвеченного файла (или папки), «Открыть в файловом менеджере» передаёт папку MiXplorer, Solid Explorer, FX и подобным (если ни один не умеет открывать папки по такому запросу, скажет об этом);
- обозреватель только читает: ничего не удаляет и не меняет.
- На вкладке «Автозагрузка» нажатие на модуль или скрипт root открывает его папку.

### Значки

Показываются у приложений, их процессов и служб: в списке процессов, во «Сведениях», в «Службах», в «Автозагрузке» и в меню действий. Если значка нет:

- **шестерёнка** у того, что не принадлежит ни одному пакету: системные демоны, нативные службы init, модули и скрипты root, потоки ядра (у служб init она окрашена по состоянию: зелёная работает, серая остановлена, оранжевая перезапускается);
- **робот Android** у приложения, значок которого получить не удалось.

Значки адаптивных приложений рисуются с маской вашего устройства (круг, «суперэллипс» и т. д.).

### Темы

В меню: **как в системе**, **светлая**, **тёмная** (тёмно-серая, как в Windows) и **AMOLED** (чисто чёрный фон: на OLED- и AMOLED-экранах пиксели гаснут и расход заряда падает). Программа не определяет тип экрана, поэтому AMOLED доступна всегда. Значки в строке состояния и панели навигации подстраиваются под выбранную тему, даже если системная тема другая.

## Сборка APK

### Вариант 1. Без компьютера (GitHub Actions)

С телефона в Termux:

```sh
pkg install git unzip
unzip /sdcard/Download/TaskMan.zip -d ~ && cd ~/TaskMan
git init -b main && git add -A && git commit -m "TaskMan"
git remote add origin https://github.com/<ник>/<репозиторий>.git
git push -u origin main        # пароль: personal access token
```

Затем на GitHub: **Actions → Build APK → Run workflow** (запускается и сам при push). Через несколько минут в **Artifacts** появятся `TaskMan-debug` (надёжный вариант) и `TaskMan-release` (меньше и быстрее, собирается отдельным шагом).

### Вариант 2. Android Studio / командная строка

```sh
./gradlew assembleDebug        # app/build/outputs/apk/debug/
./gradlew assembleRelease      # app/build/outputs/apk/release/
```

Нужен JDK 17. Локально ключ берётся из `keystore.properties` (его создаёт `dev/make-keystore.sh`). Версии: Gradle 8.9, AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01, minSdk 26.

Подпись APK описана в следующем разделе: **сделайте свой ключ**, это занимает пару минут.

## Подпись APK

Диспетчер получает root, поэтому подпись здесь вопрос безопасности: тот, у кого есть ключ, может выпустить «обновление» приложения, которое унаследует выданные ему root-права. Поэтому готового ключа в репозитории **нет**: подписывайте своим.

### Свой ключ (рекомендуется)

1. В Termux: `pkg install openjdk-17`, затем из папки проекта `sh dev/make-keystore.sh`. Скрипт создаёт ключ `keystore/taskman-release.jks` со случайным паролем, пишет `keystore.properties` для локальных сборок и печатает четыре значения.
2. На GitHub: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Создайте `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` со значениями из вывода скрипта.
3. **Сохраните файл `.jks` и пароль** в надёжном месте. Без них приложение больше не обновить поверх установленного. В git они не попадают (`.gitignore`).
4. Запустите **Build APK** заново. Debug и release теперь подписаны одним ключом, поэтому release ставится поверх debug и наоборот.

Если секреты заданы не полностью (нет пароля или алиаса), не подходят к ключу или `KEYSTORE_BASE64` скопирован не целиком, шаг **Prepare signing key** упадёт с понятным сообщением, а не подпишет APK другим ключом молча.

### Без ключа

Секреты задавать не обязательно: сборка не падает. В этом случае workflow один раз создаёт **временный ключ**, кладёт его в кэш GitHub Actions и дальше подписывает им каждую сборку. Debug и release получаются подписанными одним ключом, а новая сборка ставится поверх предыдущей. Кэш удаляется после 7 дней без запусков: тогда создаётся новый ключ, а в логе появляется предупреждение «New temporary signing key». Новую сборку придётся поставить, предварительно удалив старую. Если так не хочется, сделайте свой ключ.

### Проверка подписи

Последний шаг запуска, **Verify APK signatures**, вызывает `apksigner verify` для debug и release APK. Он падает, если APK не подписан или подпись повреждена, и показывает всё, что сообщает `apksigner`, в логе и на вкладке Summary запуска (там же указано, какой ключ использован: `private` или `temporary`). Локально то же делает `dev/verify-apk.sh`.

### Если вы ставили сборку из прежнего архива

Та сборка была подписана ключом, который лежал в репозитории с публичным паролем. Новая подписана другим ключом, поэтому один раз удалите старую версию и поставьте новую (root в Magisk / KernelSU / APatch выдайте заново).

## Как это работает с root

1. При старте приложение запускает `su` (Magisk, KernelSU или APatch покажут запрос; выдайте права). Диспетчер определяет менеджер по `/data/adb/ksud`, `/data/adb/apd`, `/data/adb/magisk`.
2. Открываются **четыре постоянные root-оболочки**: опрос, действия, тяжёлые чтения (`dumpsys`, список модулей и служб) и интерактивные чтения (`tm_props`, `tm_ls`, `readNice`, `exePath`). Долгое чтение не тормозит опрос и действия; другие тяжёлые чтения ждут своей очереди, а свойства и файловый браузер отвечают сразу.
3. Функции-помощники из `app/src/main/assets/taskmgr.sh` загружаются в оболочку один раз, дальше приложение вызывает `tm_sample`, `tm_ident`, `tm_props` и т. д.
4. Каждая команда оборачивается так, чтобы она не могла «съесть» stdin, а в конце печатается маркер с кодом возврата. Команда, зависшая дольше таймаута, убивает сессию, и та открывается заново.

**Скорость.** Один опрос читает `/proc/<pid>/{stat,statm,oom_score_adj}` встроенным `read` без единого `fork`: у `mksh` (оболочка Android) нет встроенного `printf`, поэтому вывод идёт через `print`. На 500 процессов разница между внешним `printf` и встроенным выводом в тесте составила 574 мс против 5 мс.

**KernelSU.** Оставьте для приложения профиль root по умолчанию. Слишком урезанный профиль может запретить чтение части `/proc` и `/sys`.

## Откуда берутся данные

- **Нагрузка ЦП процесса** считается как Δ(utime+stime) / Δ(все тики `/proc/stat`) и показывается долей **всей** мощности (одно ядро из 8 = 12,5%), как в Windows.
- **«Память»** процесса — приватная: `resident − shared` из `/proc/<pid>/statm`, то есть без общих библиотек и dex. RSS и PSS видны в «Свойствах».
- **Группы:** не установленный пакет (демоны) и постоянные процессы (`oom_score_adj < 0`) → «Системные»; `oom_score_adj ≤ 200` (передний план, видимые) → «Приложения»; остальное → «Фоновые».
- **Сеть:** `/proc/net/dev`; `v4-*`, `tun*`, `rmnet_ipa*` исключены, чтобы трафик не считался дважды. Без root используется `TrafficStats`.
- **GPU:** ищутся известные узлы sysfs (Adreno `kgsl`, Mali на Exynos / Tensor, MediaTek GED, devfreq). Нужного узла нет — вкладка так и скажет. Свой узел добавьте в список в `tm_sample` и в `parseGpu` (`core/Parsers.kt`).
- **Ядра и потоки GPU:** у Mali драйвер сообщает число шейдерных ядер (`gpuinfo`) и маски ядер (`core_mask`, нужен root): так видно, сколько ядер есть и сколько включено. «Потоки» это предел вычислений OpenGL ES (потоков в рабочей группе, размер группы, общая память), его программа спрашивает у драйвера без root через маленький внеэкранный контекст. Android не отдаёт нагрузку отдельных ядер GPU, а у Adreno число ядер не публикуется, поэтому там прочерк.
- **Память (диск):** `/proc/diskstats` (нужен root). Берутся только целые устройства (`mmcblk0`, `sda`…), без разделов, `dm-*`, `loop`, `zram`, поэтому байты не считаются дважды. Время активности это доля интервала, когда у самого занятого устройства были запросы в работе (как `%util` в iostat). Заполнение раздела `/data` берётся через `StatFs` и работает без root.
- **Диск процесса:** `read_bytes + write_bytes` из `/proc/<pid>/io` (нужен root): сколько байт процесс реально обменял с накопителем, без попаданий в кэш. Скорость считается за те же 3 секунды, что и остальные столбцы. В шапке «Диск» показано время активности самого занятого накопителя.
- **Сеть приложения:** счётчики по приложениям (uid) из `/proc/net/xt_qtaguid/stats` (нужен root). Ядро считает трафик на приложение, а не на процесс, поэтому значение есть у строк приложений, а у отдельных процессов и системных демонов стоит прочерк (их uid общий для многих служб). **Ограничение:** новые ядра ведут эти счётчики в eBPF-таблицах, которые оболочка прочитать не может. Если на вашем устройстве файла `xt_qtaguid` нет, столбец «Сеть» остаётся пустым, а над списком появляется пояснение. В шапке «Сеть» это общий трафик телефона (из `/proc/net/dev`), он работает всегда.
- **Автозагрузка приложений:** `PackageManager.queryBroadcastReceivers` + `getComponentEnabledSetting`, переключение через `pm enable|disable`.

## Ограничения

- Без root Android скрывает `/proc` других приложений, `/proc/stat`, `dumpsys`. Приложение покажет что сможет и скажет об этом.
- «Приоритет» вызывает `renice -n`; у разных версий toybox семантика `-n` может отличаться. После изменения программа перечитывает nice и показывает фактическое значение.
- Разбор `dumpsys activity services` рассчитан на формат Android 8–15; если OEM его изменил, список служб Android будет пустым, а нативные службы init продолжат работать.
- Обозреватель файлов использует `ls -lA`; формат вывода разобран для toybox и GNU `ls`. Нестандартный `ls` покажет сырое сообщение об ошибке.
- Завершение системных процессов (`system_server`, `zygote`, `surfaceflinger`…) перезагружает оболочку Android. Перед этим программа просит подтверждение.

## Статус проверки

- Ядро (`core/`: разбор `/proc` и `ls`, математика нагрузки, протокол оболочки, таймауты) покрыто тестами `dev/run-core-tests.sh`. Они проходят на `dash` и на `mksh` с `toybox`, то есть на оболочке и утилитах Android.
- Весь код приложения проверялся компилятором против API Android 35 и заглушек Compose: опечаток, пропущенных импортов и несовпадений типов нет.
- Выбор ключа для подписи (переменные окружения, `keystore.properties`, пустые значения, отсутствующий файл) прогнан в настоящем Gradle 8.9 на JDK 17. Созданный скриптом ключ читается JDK 17 и подписывает, `dev/verify-apk.sh` проверен на подставном `apksigner`.
- Реальная сборка Android (AGP) и запуск на устройстве в среде разработки были недоступны. Если сборка упадёт, пришлите лог шага **Build debug APK**.

## Структура

```
app/src/main/assets/taskmgr.sh        функции для su: опрос, ident, props, модули, службы
app/src/main/java/com/taskman/root/
  core/    чистый JVM: Shell.kt (сессии), Parsers.kt, Engine.kt (дельты), Grouping.kt, Files.kt (ls), Format.kt
  data/    SystemRepo.kt (su/sh, автозагрузка, Wi-Fi), AppIndex.kt, GlProbe.kt (пределы GPU через OpenGL ES)
  ui/      MainViewModel.kt, экраны вкладок, Sheets.kt (действия), FileBrowser.kt, Intents.kt, Prefs.kt, Theme.kt, Components.kt
dev/       тесты ядра (run-core-tests.sh), создание ключа (make-keystore.sh), проверка подписи (verify-apk.sh)
```
