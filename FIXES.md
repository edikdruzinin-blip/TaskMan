# TaskMan 1.1.0 — что исправлено и улучшено

Это исправленная сборка по итогам ревью. Версия `versionCode = 3`, `versionName = "1.1.0"`.
Компиляция в среде ревью не запускалась (не было JDK 17 / Android SDK), поэтому перед раздачей
обязательно прогоните сборку в GitHub Actions или Android Studio.

## UI для телефона (1.1.0)

- **Нижняя навигация на телефоне.** Пять вкладок переехали в `NavigationBar` внизу экрана, под большой
  палец; на экранах шире 600 dp остаётся прежняя верхняя `ScrollableTabRow` со всеми вкладками.
- **Карточки процессов.** На телефоне строка стала двух-трёхстрочной карточкой: имя и пакет, под ними
  Диск и Сеть, справа ЦП и Память. Горизонтальная прокрутка четырёх столбцов больше не нужна.
- **Итоги сверху.** На телефоне вместо широкой шапки таблицы — компактная полоса «ЦП / Память / Диск /
  Сеть» с цветными маркерами.
- **Сортировка в меню.** Вместо мелких кликабельных заголовков — кнопка «Сортировка: ЦП ▼» с выпадающим
  списком; на планшете заголовки таблицы по-прежнему работают.
- **Компактные «Сведения».** На телефоне — список в две-три строки (PID, пользователь, состояние,
  потоки, nice, OOM) с ЦП и памятью справа; на широком экране — прежняя таблица.
- **Плитки производительности 2×3.** На телефоне все шесть плиток видны сеткой, а не уезжают вправо;
  графики — под ними.
- **Безопасные шторки.** В шторках процессов, приложений и служб опасные действия («Завершить»,
  SIGTERM/SIGKILL, отключение автозагрузки) перенесены вниз, под разделитель; случайный тап по верхней
  части больше не убивает процесс.
- **Крупнее тапы.** Карточки процессов — минимум 64/56 dp, стрелка раскрытия — 44 dp, нижняя навигация
  и кнопка сортировки — стандартные 48 dp; на телефоне фиксированные высоты строк заменены на `heightIn`.

### Что проверить на телефоне

1. Портрет 360 dp: пять подписей внизу не обрезаны, все вкладки доступны одним пальцем.
2. Строка процесса: имя, пакет, Диск/Сеть и справа ЦП/Память читаются без горизонтальной прокрутки.
3. «Производительность»: все шесть плиток видны сеткой 2×3, выбранная подсвечена, график ниже.
4. «Сведения»: сортировка открывается, строки не разъезжаются при обновлении и прокрутке.
5. Поворот: на широком экране возвращается таблица и верхние вкладки, состояние вкладки сохраняется.
6. Крупный системный шрифт (1.3–2.0): текст в карточках не обрезается по высоте.

## Критичные исправления

- **ANR при выходе.** `onCleared()` больше не вызывает `repo.close()` на главном потоке: сессии
  закрываются в фоновом daemon-потоке, поэтому долгий `dumpsys`/`tm_sample` не подвешивает выход.
- **Фоновый цикл 20 Гц.** `startLoop()` переписан на `combine(_speed, _foreground, _root)` +
  `collectLatest`: в фоне, на паузе и во время проверки root опрос не крутится; при смене скорости
  цикл перезапускается.
- **Разрешения Android 12+.** В манифест добавлен `ACCESS_COARSE_LOCATION`; запрос SSID теперь идёт
  через `RequestMultiplePermissions` с FINE + COARSE (раньше FINE-only игнорировался на Android 12+).
- **Ошибки выборки видны.** `ListData.error` + `ErrorBox`/баннер с кнопкой «Повторить» на вкладках
  «Процессы», «Сведения» и «Производительность». `vm.retry()` заново проверяет root, если он потерян.
- **Нельзя убить самого себя.** `signal()` и `forceStop()` защищены по `ownPid`/`ownPackage`;
  в меню своей строки пункты «Завершить» скрыты.
- **Четвёртая оболочка.** `SystemRepo` получил отдельную `interactive`-сессию для `tm_props`,
  `tm_ls`, `readNice`, `exePath`: файловый браузер и «Свойства» больше не ждут 40-секундный `dumpsys`.
- **Подтверждения.** «Остановить службу»/«Принудительно остановить» на вкладке «Службы» и отключение
  автозагрузки/force-stop на «Автозагрузке» теперь спрашивают подтверждение.
- **`retryRoot`.** Повторный запрос root игнорируется, пока идёт проверка; после смены root-состояния
  вкладки «Автозагрузка»/«Службы» перезагружаются, а не остаются в вечном `LoadingBox`.

## Важные исправления

- Списки: обновление не чаще раза в 3 с; текст README и пункта меню больше не обещает ровно 3 с при
  низкой скорости.
- `loadStartup()`/`loadServices()` ловят исключения и не роняют приложение; при смене root во время
  загрузки состояния перезагружаются.
- `stopService()` показывает «Готово»/реальную ошибку, а не сырой `Stopping service: Intent {...}`.
- `setComponents()` выполняет `pm` по одной команде и считает реальные успехи (нет ложного «N
  компонентов» при частичном провале).
- `hasError()` больше не считает ошибкой любое слово «Exception» в имени компонента.
- Кэш идентичности процессов не запоминает неудачу навсегда: нечитаемый процесс опрашивается снова.
- `sysconf` с `-1` заменяется на 4096/100; отрицательный размер страницы больше не ломает память/CPU.
- Нижняя панель файлового браузера получила `navigationBarsPadding()`.
- `-keepclassmembers enum * { *; }` — имена enum, которые сохраняются в `Prefs`, не переименуются R8.
- Per-app сеть: `qtaguid` больше не суммирует VPN/туннели (`tun*`, `v4-*`, `ipsec*`, `rmnet_ipa*`), нет
  двойного счёта.
- `toMhz()` корректно понимает частоты ниже 100 МГц.
- Иконки: `clearMissing()` после перезагрузки индекса пакетов — установленное приложение больше не
  остаётся с «роботом» до перезапуска.
- GPU: если OpenGL-зонд вернул `null`, следующий тап по вкладке пробует снова.
- `tm_modules` не спотыкается о модуль без `module.prop`.
- `dev/run-core-tests.sh` использует `${TMPDIR:-/tmp}` (работает в Termux); тест `uid names` больше
  не заканчивается `|| true`.
- CI: release-сборка больше не `continue-on-error` (сломанный release делает run красным), добавлен
  `pull_request`.

## Что осталось из ревью (сознательно не менялось)

- Полная проверка сборки AGP/R8 и запуск на устройстве — обязательны; в среде ревью их не было.
- Доступность: на планшете остаются фиксированные высоты строк и стрелка 36 dp; у графиков по-прежнему
  нет semantics. На телефоне строки уже тянутся по высоте, но TalkBack-описания графиков стоит добавить.
- Часть ru-локализации (`perf_storage` = «Память» и т. п.) — тексты не трогал, чтобы не раздувать diff.
- `Intents.openFolder` всё ещё использует `file://` + сброс StrictMode VmPolicy.
- `versionCode` теперь 3 только в этой сборке; для следующих обновлений его нужно поднимать (или
  подставлять номер CI-запуска).
- `README` по-прежнему честно говорит, что реальная сборка на устройстве не проверялась.

сборка ставится поверх предыдущей при том же ключе.
