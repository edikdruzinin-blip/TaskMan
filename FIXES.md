# TaskMan 1.2.0 — интерфейс в стиле Windows 11

Версия `versionCode = 4`, `versionName = "1.2.0"`. Меняется только оформление и навигация; ядро, данные,
действия и тексты сообщений остались прежними. **Сборка Android в среде правки не запускалась**: перед
раздачей прогоните GitHub Actions или Android Studio. Если упадёт, пришлите лог шага **Build debug APK**.

## Что изменилось

- **Тема** (`Theme.kt`): палитра Fluent (Mica, акцент, обводки), шкала шрифтов Windows 11 без трекинга,
  скругления 4 / 8 dp, тепловая карта акцентным цветом (`heatBackground`), `surfaceTint` отключён.
- **Окно** (`App.kt`): на телефоне заголовок страницы + состояние root + поиск + «Параметры», внизу плоская
  панель вкладок с акцентной чертой; от 600 dp строка заголовка с постоянным полем поиска и навигационная
  панель слева (гамбургер сворачивает; от 840 dp раскрыта сама). Страница лежит на скруглённом слое с рамкой.
- **«Параметры»** (`Sheets.kt`): скорость обновления, тема, потоки ядра и повторный запрос root собраны в
  один лист вместо выпадающего меню и отдельного диалога темы (`DialogModel.Theme` и `ThemeDialog` удалены).
- **Процессы**: четыре плитки итогов с тепловой подсветкой (нажатие сортирует), «таблетки» ЦП/Память в
  строке, шапка таблицы на широком экране с шевроном сортировки и подсветкой, заголовки групп.
- **Производительность**: плитки-карточки, крупные числа (`StatGrid`), градиентные графики, закруглённые
  полосы состава, разделитель между списком ресурсов и графиком.
- **Автозагрузка / Службы / Сведения**: переключатели WinUI с подписью «Вкл. / Выкл.», вкладки-pivot вместо
  чипов, цветная точка состояния у служб init, значок «foreground» как таблетка.
- **Диалоги и шторки**: ContentDialog (`FluentDialog`), список действий как контекстное меню Windows,
  выбор приоритета с отметкой текущего значения.
- **Обозреватель файлов**: адресная строка, значки папок и файлов, кнопки WinUI.
- **Ресурсы**: 17 векторных значков (`ic_tab_*`, `ic_fl_*`, `ic_logo`); три новые строки
  (`settings_title`, `toggle_on`, `toggle_off`), RU и EN по 231.
- **Новый файл** `ui/Fluent.kt` с общими элементами: `ContentLayer`, `SearchField`, `WinToggle`,
  `WinButton`, `FluentDialog`, `HeatPill`, `PivotRow`, `ChoiceRow`.

Сигнатуры публичных функций (`ChipRow`, `SortBar`, `StatGrid`, `LineGraph`, `HeatCell`, `AppIcon` ...)
сохранены, `StatGrid` получил необязательный параметр `large`.

## Что проверено здесь

- Синтаксис всех `.kt` (разбор деревом tree-sitter): ошибок нет.
- Импорты: каждый использованный символ Compose / Material3 импортирован, лишних импортов нет.
- Все вызовы функций проекта сверены с их параметрами (268 функций): расхождений нет.
- `weight` и `align` стоят только внутри `Row` / `Column` / `Box` подходящего вида.
- Все `R.string.*` и `R.drawable.*` существуют; RU и EN совпадают.
- Значки отрисованы и просмотрены на светлом и тёмном фоне.
- Имена именованных параметров вызовов Compose / Material3 сверены с таблицей сигнатур: расхождений нет.
- Контраст основного текста на самой яркой тепловой подсветке: 9,7:1 (светлая), 5,3:1 (тёмная), 7,6:1 (AMOLED);
  подписи на сильно подсвеченных ячейках переключаются на основной цвет текста.

## Что проверить на телефоне

1. Светлая, тёмная и AMOLED-темы: страница отделена рамкой от фона, текст читается на подсвеченных ячейках.
2. Портрет 360 dp: пять подписей внизу не обрезаны; «Производительность» в заголовке помещается.
3. Строка процесса: «ЦП» и «Память» на таблетках, нажатие на плитку сверху меняет сортировку.
4. «Параметры»: смена темы и скорости применяется сразу, переключатель потоков ядра работает.
5. Планшет / альбомная ориентация: навигационная панель сворачивается, поле поиска фильтрует списки.
6. Крупный системный шрифт: строки на телефоне не обрезаются по высоте.

## Сознательно не делалось

- Свой шрифт: Segoe UI нельзя распространять, Selawik (его открытая замена) не содержит кириллицы.
- Эффект Mica (размытие обоев) недоступен на Android; Mica передан цветом фона.
- Выбор строки и кнопка «Завершить задачу» в командной строке, как в Windows: нажатие по-прежнему открывает
  шторку действий, потому что опасные действия в ней отделены и защищены от случайного тапа.

# TaskMan 1.1.0 — что исправлено и улучшено

Это исправленная сборка по итогам ревью. Версия `versionCode = 3`, `versionName = "1.1.0"`.
Компиляция в среде ревью не запускалась (не было JDK 17 / Android SDK), поэтому перед раздачей
обязательно прогоните сборку в GitHub Actions или Android Studio.

## UI для телефона (1.1.0)

- **Нижняя навигация на телефоне.** Пять вкладок переехали в `NavigationBar` внизу экрана, под большой
  палец; на экранах шире 600 dp остаётся прежняя верхняя `ScrollableTabRow` со всеми вкладками.
- **Карточки процессов.** На телефоне строка стала двух-трёхстрочной карточкой: имя и пакет, под ними
  Диск и Сеть, справа ЦП и Память. Горизонтальная прокрутка четырёх столбцов больше не нужна.
- **Итоги сверху.** На телефоне вместо широкой шапки таблицы — компактная полоса «ЦП / Память / Диск /
  Сеть» с цветными маркерами.
- **Сортировка в меню.** Вместо мелких кликабельных заголовков — кнопка «Сортировка: ЦП ▼» с выпадающим
  списком; на планшете заголовки таблицы по-прежнему работают.
- **Компактные «Сведения».** На телефоне — список в две-три строки (PID, пользователь, состояние,
  потоки, nice, OOM) с ЦП и памятью справа; на широком экране — прежняя таблица.
- **Плитки производительности 2×3.** На телефоне все шесть плиток видны сеткой, а не уезжают вправо;
  графики — под ними.
- **Безопасные шторки.** В шторках процессов, приложений и служб опасные действия («Завершить»,
  SIGTERM/SIGKILL, отключение автозагрузки) перенесены вниз, под разделитель; случайный тап по верхней
  части больше не убивает процесс.
- **Крупнее тапы.** Карточки процессов — минимум 64/56 dp, стрелка раскрытия — 44 dp, нижняя навигация
  и кнопка сортировки — стандартные 48 dp; на телефоне фиксированные высоты строк заменены на `heightIn`.

### Что проверить на телефоне

1. Портрет 360 dp: пять подписей внизу не обрезаны, все вкладки доступны одним пальцем.
2. Строка процесса: имя, пакет, Диск/Сеть и справа «ЦП …» и «Память …» читаются без горизонтальной прокрутки.
3. «Производительность»: все шесть плиток видны сеткой 2×3, выбранная подсвечена, график ниже; у GPU-плитки
   две строки (нагрузка и частота), как у Wi-Fi, поэтому она не выглядит «пустой».
4. «Сведения»: сортировка открывается, строки не разъезжаются при обновлении и прокрутке.
5. Поворот: на широком экране возвращается таблица и верхние вкладки, состояние вкладки сохраняется.
6. Крупный системный шрифт (1.3–2.0): текст в карточках не обрезается по высоте.

### Правки по скриншоту 20:00

- GPU-плитка получила вторую строку подписи (частота или «—»), поэтому её карточка по высоте и заполнению
  совпадает с соседней Wi-Fi, а не выглядит пустым квадратом.
- В карточках процессов значения подписаны явно: «ЦП 18%», «Память 1,23 ГБ»; так видно, какое приложение
  или системный процесс расходует ресурсы, а не только общие итоги сверху.

### Сборка

- По логу CI от 16:09 исправлена отсутствующая ссылка `Modifier.fillMaxWidth()` в `DetailsScreen.kt`
  (не был импортирован `androidx.compose.foundation.layout.fillMaxWidth`). Повторный запуск должен
  пройти дальше этой ошибки.

## Критичные исправления

- **ANR при выходе.** `onCleared()` больше не вызывает `repo.close()` на главном потоке: сессии
  закрываются в фоновом daemon-потоке, поэтому долгий `dumpsys`/`tm_sample` не подвешивает выход.
- **Фоновый цикл 20 Гц.** `startLoop()` переписан на `combine(_speed, _foreground, _root)` +
  `collectLatest`: в фоне, на паузе и во время проверки root опрос не крутится; при смене скорости
  цикл перезапускается.
- **Разрешения Android 12+.** В манифест добавлен `ACCESS_COARSE_LOCATION`; запрос SSID теперь идёт
  через `RequestMultiplePermissions` с FINE + COARSE (раньше FINE-only игнорировался на Android 12+).
- **Ошибки выборки видны.** `ListData.error` + `ErrorBox`/баннер с кнопкой «Повторить» на вкладках
  «Процессы», «Сведения» и «Производительность». `vm.retry()` заново проверяет root, если он потерян.
- **Нельзя убить самого себя.** `signal()` и `forceStop()` защищены по `ownPid`/`ownPackage`;
  в меню своей строки пункты «Завершить» скрыты.
- **Четвёртая оболочка.** `SystemRepo` получил отдельную `interactive`-сессию для `tm_props`,
  `tm_ls`, `readNice`, `exePath`: файловый браузер и «Свойства» больше не ждут 40-секундный `dumpsys`.
- **Подтверждения.** «Остановить службу»/«Принудительно остановить» на вкладке «Службы» и отключение
  автозагрузки/force-stop на «Автозагрузке» теперь спрашивают подтверждение.
- **`retryRoot`.** Повторный запрос root игнорируется, пока идёт проверка; после смены root-состояния
  вкладки «Автозагрузка»/«Службы» перезагружаются, а не остаются в вечном `LoadingBox`.

## Важные исправления

- Списки: обновление не чаще раза в 3 с; текст README и пункта меню больше не обещает ровно 3 с при
  низкой скорости.
- `loadStartup()`/`loadServices()` ловят исключения и не роняют приложение; при смене root во время
  загрузки состояния перезагружаются.
- `stopService()` показывает «Готово»/реальную ошибку, а не сырой `Stopping service: Intent {...}`.
- `setComponents()` выполняет `pm` по одной команде и считает реальные успехи (нет ложного «N
  компонентов» при частичном провале).
- `hasError()` больше не считает ошибкой любое слово «Exception» в имени компонента.
- Кэш идентичности процессов не запоминает неудачу навсегда: нечитаемый процесс опрашивается снова.
- `sysconf` с `-1` заменяется на 4096/100; отрицательный размер страницы больше не ломает память/CPU.
- Нижняя панель файлового браузера получила `navigationBarsPadding()`.
- `-keepclassmembers enum * { *; }` — имена enum, которые сохраняются в `Prefs`, не переименуются R8.
- Per-app сеть: `qtaguid` больше не суммирует VPN/туннели (`tun*`, `v4-*`, `ipsec*`, `rmnet_ipa*`), нет
  двойного счёта.
- `toMhz()` корректно понимает частоты ниже 100 МГц.
- Иконки: `clearMissing()` после перезагрузки индекса пакетов — установленное приложение больше не
  остаётся с «роботом» до перезапуска.
- GPU: если OpenGL-зонд вернул `null`, следующий тап по вкладке пробует снова.
- `tm_modules` не спотыкается о модуль без `module.prop`.
- `dev/run-core-tests.sh` использует `${TMPDIR:-/tmp}` (работает в Termux); тест `uid names` больше
  не заканчивается `|| true`.
- CI: release-сборка больше не `continue-on-error` (сломанный release делает run красным), добавлен
  `pull_request`.

## Что осталось из ревью (сознательно не менялось)

- Полная проверка сборки AGP/R8 и запуск на устройстве — обязательны; в среде ревью их не было.
- Доступность: на планшете остаются фиксированные высоты строк и стрелка 36 dp; у графиков по-прежнему
  нет semantics. На телефоне строки уже тянутся по высоте, но TalkBack-описания графиков стоит добавить.
- Часть ru-локализации (`perf_storage` = «Память» и т. п.) — тексты не трогал, чтобы не раздувать diff.
- `Intents.openFolder` всё ещё использует `file://` + сброс StrictMode VmPolicy.
- `versionCode` теперь 3 только в этой сборке; для следующих обновлений его нужно поднимать (или
  подставлять номер CI-запуска).
- `README` по-прежнему честно говорит, что реальная сборка на устройстве не проверялась.

## Проверка перед сборкой и одна правка

Версия 1.1.0 из `TaskMan-phone.zip` прогнана через инструменты проверки; сама сборка Android в этой среде не запускалась.

- Ядро и слой данных скомпилированы против настоящего Android API 34, интерфейс против заглушек API Compose: ошибок и лишних импортов нет.
- Тесты ядра (`dev/run-core-tests.sh`) проходят на `dash` и на `mksh` с `toybox` (оболочка и утилиты Android).
- Все XML-ресурсы корректны, строки RU и EN совпадают (228 ключей), ссылок на несуществующие ресурсы нет. Значки вкладок отрисованы и просмотрены.
- Workflow и скрипты `dev/*.sh` прошли проверку синтаксиса; блок выбора ключа подписи в `app/build.gradle.kts` не менялся и ранее был проверен в Gradle 8.9.
- **Правка в `.github/workflows/build.yml`:** при событии `pull_request` кэш временного ключа подписи больше не восстанавливается. Иначе workflow из чужого pull request мог бы прочитать этот ключ. Для таких запусков создаётся одноразовый ключ, который никуда не сохраняется.
- Не проверено: сборка AGP и работа на устройстве. Перед раздачей APK прогоните **Build APK** и проверьте шаг **Verify APK signatures**.
